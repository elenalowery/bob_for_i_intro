IBM i Modes: Hands-On Exercise

Try both IBM i modes and compare how Bob responds — notice which skills and tools are invoked automatically

IBM i Developer Mode Focus: COBOL on IBM i
  1. 1

    Switch to IBM i Developer mode, then ask Bob to explain the structure of a COBOL program.

    Prompt

    Explain the structure of a COBOL program on IBM i. What are the four divisions and what does each one do?

  2. 2

    Ask Bob to generate a COBOL program that reads from a physical file.

    Prompt

    Generate a COBOL on IBM i program that reads all records from a physical file called CUSTOMERS and displays each customer's name and account number.

  3. 3

    Ask Bob to modernize a COBOL program to use embedded SQL.

    Prompt

    Rewrite the CUSTOMERS program to use embedded SQL instead of native file I/O. Use a cursor to fetch all rows.

  4. 4

    Ask Bob to review code for best practices.

    Prompt

    Review this COBOL program for IBM i best practices. Flag any OPM-style patterns that should be updated for ILE COBOL.

  5. 5

    Ask Bob to generate a unit test stub for a COBOL procedure.

    Prompt

    Generate an RPGUnit-style test stub for a COBOL procedure that validates customer account numbers. What testing approach would you recommend?

    ⓘ  Observe which COBOL skills Bob auto-loads in its reasoning.
IBM i Database Mode Focus: Db2 for i & SQL
  1. 1

    Switch to IBM i Database mode, then ask Bob about converting DDS to DDL.

    Prompt

    What is the recommended approach for migrating a DDS physical file definition to a Db2 for i DDL table? What are the key differences to watch for?

  2. 2

    Ask Bob to generate a SQL query using IBM i system catalog views.

    Prompt

    Write a SQL query using QSYS2 system catalog views to list all physical files in library SAMCO, including their record count and last modified date.

  3. 3

    Ask Bob to analyze SQL performance.

    Prompt

    Analyze this SQL query for performance issues on Db2 for i. Suggest index strategy improvements and explain how to verify them using the plan cache.

  4. 4

    Ask Bob to explain journaling and commitment control.

    Prompt

    Explain how journaling and commitment control work on IBM i. When should I use COMMIT and ROLLBACK in a Db2 for i application?

  5. 5

    Ask Bob to generate a stored procedure.

    Prompt

    Generate a Db2 for i SQL stored procedure that accepts a customer ID as input and returns the customer's order history for the last 12 months.

    ⓘ  Compare the Db2 skills Bob invokes here vs. the COBOL skills from the Developer mode prompts.
